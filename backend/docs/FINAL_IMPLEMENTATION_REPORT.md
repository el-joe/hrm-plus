## English summary

HRM Plus is complete as specified in `doc.md`, with the external integrations shipped as interfaces plus clearly
labelled simulated adapters where client inputs are still missing.

- **Delivered:** Laravel 13 / PHP 8.3 backend with an Admin dashboard (18 modules, permission-driven sidebar,
  dynamic RBAC with 11 default roles, 53 permission modules / 246 permissions, branch / department / group data
  scopes, audit and sensitive-access logging), an Employee web portal, a versioned REST API (`/api/v1`, ~100
  endpoints, OpenAPI at `/docs/api`), and a Flutter employee app (25 screens, Arabic RTL + English LTR, GPS + face
  check-in, push-ready). Attendance engine (device / mobile / manual / import sources, raw events vs processed days,
  bulk "mark all present except…"), leave engine, payroll engine (versioned structures, allowances, deductions,
  statutory tables, loans, branch-scoped settlements, two-level approval, finalisation lock, corrections, reversal,
  final settlement, Arabic PDF payslips), performance, training, assets, HR requests, announcements, disciplinary,
  notifications, 22 dashboard widgets and 52 reports with Excel / CSV / Arabic PDF export.
- **Tests:** backend **1424 passed** (final full run, 2026-11-12); Flutter **107 passed, 5 live-API tests skipped** (run on demand against a
  real backend).
- **Open client inputs:** B3 fingerprint device model, B4 face-verification provider, B5 Firebase / APNs,
  B6 SMTP, B7 statutory rules, B8 brand and bundle id, B9 Android licences.
- **Web portal check-in (client request, `44aa52a`):** employees check in / out from the portal in a browser with
  the same server rules as the app (geofence, accuracy, shift window, drift, repeated attempts, face with HR-review
  fallback); per-policy switches; channel column and filter in the review queue; requires HTTPS.
- **Final polish pass:** unified Arabic terminology (departments «الأقسام», deductions «الاستقطاعات», positions
  «الوظائف», «القضايا التأديبية», «الأحداث الأولية», «مراجعة تسجيلات الجوال والويب»), translated labels for all
  182 audit events (dashboard and audit log), `.env.example` completed (`REPORTS_*` and others), HR letters on the
  shared `ArabicPdf`, mPDF font cache untracked, docs updated and the manual PDF regenerated.
- **Operational `.env` values → system settings:** sign-in lockout, mobile token lifetime, session cookie SameSite /
  Secure, security headers / CSP / HSTS / extra origins, export limit (Settings → Security), report export thresholds
  and PDF row limit (new Settings → Reports), daily log days (Settings → Data retention); one-off data migration
  copies values still set in `.env`.
- **Docs:** see the list in section 9.

## 1. نظرة عامة

نظام HRM Plus نظام متكامل لإدارة الموارد البشرية يتكون من:

- **الخلفية وتطبيق الويب** (`backend/`): Laravel 13 على PHP 8.3 وMySQL 8، بواجهتين منفصلتين: **لوحة الإدارة** و**بوابة الموظف**، بـ Blade وTailwind CSS وJavaScript أصلي فقط (بلا Livewire أو Alpine أو Vue أو React أو jQuery)، وواجهة برمجية REST مُصدَّرة `/api/v1`.
- **تطبيق الجوال للموظفين** (`application/`): Flutter، للموظفين فقط.
- **التصميم:** نظام تصميم وقوالب تخطيط في Figma (بقرار من العميل اقتصر Figma على نظام التصميم والقوالب، وبُنيت الشاشات مباشرة في الكود).

نوعا حسابات فقط: **إداري** و**موظف**؛ الأدوار الإدارية صلاحيات قابلة للتهيئة، ويمكن ربط الحساب الإداري بملف موظف.

## 5. قرارات وفجوات معروفة

### 5.1 قرارات اتخذها العميل أو قائد المشروع

1. **Figma:** يقتصر على نظام التصميم والمكونات وقوالب التخطيط؛ الشاشات بُنيت مباشرة في الكود (قرار العميل 2026-11-11).
2. **التحقق بالوجه اختياري افتراضيًا** إلى أن يتوفر مزوّد حقيقي.
3. **الإجراءات التأديبية مقيدة:** عرض الملفات لمدير النظام ومدير الموارد البشرية فقط؛ الآخرون يبلّغون ويتابعون بلاغاتهم.
4. **مدير الموارد البشرية** يملك تعديل البيانات المالية (لتطبيق طلبات تغيير الحساب البنكي)، لكنه لا يُعد المسيرات ولا يُقفلها.
5. **فصل مهام الرواتب:** الإعداد (محاسب الرواتب) ≠ الاعتماد بمستويين (الموارد البشرية ثم المالية) ≠ الإقفال النهائي (المسؤول المالي).
6. **التقارير:** الوصول لمجال تقارير يتطلب صلاحية عرض الوحدة، و`reports.manage` يفتح كل المجالات (المرحلة 11).
7. **تناسب الرواتب:** المبلغ × الأيام ÷ أيام الفترة، بتقريب واحد لكل بند (المرحلة 11).
8. **تسجيل الحضور من بوابة الويب:** طلب العميل أثناء المرحلة 11؛ نُفّذ (`44aa52a`) بمسار الخادم نفسه المستخدم للتطبيق، مع إعدادين لكل نسخة سياسة حضور («السماح بتسجيل الحضور من بوابة الويب»، «يجب أن يكون تسجيل الويب داخل النطاق الجغرافي»). المتصفح لا يبلّغ عن فحص الحيوية ولا الموقع الوهمي.
9. عملة بيانات العرض EGP، ومنطقتها الزمنية Africa/Cairo، وعطلات العرض مصرية توضيحية.

### 5.2 افتراضات (من سجل الافتراضات)

- A1: شركة واحدة بفروع متعددة (لا تعدد مستأجرين).
- A6: لا تسجيل حضور بلا اتصال؛ التطبيق يتطلب الشبكة.
- A8: الاختبارات على قاعدة MySQL منفصلة (لعدم توفر pdo_sqlite).
- A9: الإداري بعدة قيود نطاق يرى ما يطابق **أيًا** منها (يمكن تحويله إلى «و» بطلب العميل).

### 5.3 فجوات معروفة (غير مبنية في هذا الإصدار)

1. **المصادقة متعددة العوامل (2FA):** غير مبنية (المواصفات تقول «اختيارية»).
2. **شاشة تعديل مسارات الاعتماد:** المسارات الستة عشر معرّفة عند التثبيت؛ الصلاحيتان `approvals.view/manage` محجوزتان بلا شاشة.
3. **النطاقات الجغرافية المضلعة:** المدعوم دائري (نقطة + نصف قطر) فقط.
4. **محوّلات أجهزة حقيقية ومزوّد وجه حقيقي:** بانتظار B3/B4.
5. **ملف بنكي بصيغة بنك محدد:** المتاح ملف CSV/XLSX عام.
6. **أهلية الإجازة حسب الحالة الاجتماعية أو الديانة:** غير مبنية (لم تطلبها المواصفات).
7. **لا توجد واجهة برمجية للإدارة** ولا للإجراءات التأديبية في تطبيق الجوال (التطبيق للموظفين، والمواصفات لا تطلب شاشة تأديب في الجوال).
8. **رسائل بريد المرشحين** رسائل مباشرة خارج نظام قوالب الإشعارات (لا حساب للمرشح).
9. **عرض العمل** صفحة HTML قابلة للطباعة (لا PDF).
10. **شاشات قديمة** لم تتحول كلها إلى المنسق المركزي للتواريخ والأرقام (تُحوَّل عند تعديلها).

## 6. ملخص خطوات التثبيت

التفاصيل الكاملة في DEPLOYMENT_GUIDE_AR.md.

```bash
cd backend
composer install --no-dev --optimize-autoloader
npm ci && npm run build
cp .env.example .env        # APP_ENV=production, APP_DEBUG=false, APP_URL=https://…, DB_*, MAIL_*, LOG_LEVEL=warning
php artisan key:generate --force
php artisan migrate --seed --force
php artisan hrm:create-super-admin --name="…" --email=…
php artisan config:cache && php artisan route:cache && php artisan view:cache && php artisan event:cache
# cron:   * * * * * cd /path/backend && php artisan schedule:run >> /dev/null 2>&1
# worker: php artisan queue:work --queue=default   (Supervisor)
# الترقيات: php artisan migrate --force && php artisan permissions:sync
```

ثم من الواجهة: الإعدادات، الهيكل التنظيمي، الورديات، الإجازات، الرواتب والقواعد النظامية، الموظفون، المستخدمون الإداريون.

**تطبيق الجوال:** `flutter build appbundle|ipa --release --dart-define=API_BASE_URL=https://…/api/v1` بعد إضافة ملفات Firebase ومعرّف الحزمة الحقيقي.

**بيئة العرض:** `php artisan migrate:fresh --seed` (غير الإنتاج) يزرع شركة عرض و61 موظفًا وحسابًا لكل دور (`DEV_ACCOUNTS.md`).

## 7. الأمان — ملخص

- الصلاحيات تُفرض في الخادم على كل مسار (مع اختبار يغطي كل مسارات الإدارة)، ونطاق البيانات يُطبق على كل الاستعلامات والتقارير والتصدير.
- ملكية صارمة في البوابة والواجهة البرمجية (404 لأي سجل لا يخص الموظف).
- تشفير أرقام الهوية والجوازات والحسابات البنكية وبيانات اتصال الأجهزة ومراجع الوجه والقيم السرية؛ رموز الأجهزة ورموز OTP مجزأة.
- لا صور أو قوالب حيوية بنص صريح؛ موافقة، احتفاظ، وحذف.
- سجل تدقيق كامل (من، ماذا، متى، القيمة القديمة والجديدة، السجل المتأثر)، وسجل الدخول، وسجل الوصول الحساس، مع حجب القيم الحساسة.
- حماية CSRF وXSS (تعقيم النصوص الغنية)، استعلامات مُعَدّة، التحقق من الملفات المرفوعة، ملفات خاصة غير مكشوفة، حدود معدل، ترويسات أمان وCSP وHSTS.
- لا حذف لمسيرات مقفلة أو حضور تاريخي عبر عمليات CRUD العادية.

## 8. المخاطر والتوصيات قبل التشغيل الفعلي

1. إدخال القواعد النظامية المعتمدة قانونيًا (B7) ومراجعة مسير تجريبي موازٍ لشهر على الأقل.
2. ربط SMTP (B6) وFirebase (B5) واختبار التسليم.
3. عدم تفعيل التحقق بالوجه «مطلوب» قبل ربط مزوّد حقيقي (B4)؛ إجراء تقييم أثر الخصوصية.
4. استخدام استيراد ملفات الأجهزة حتى يتوفر محوّل الجهاز الحقيقي (B3)، ثم اختبار ميداني للمحوّل.
5. نشر النظام بـ HTTPS (ضروري للجلسات والتطبيق والتسجيل من البوابة).
6. سياسة نسخ احتياطي تشمل قاعدة البيانات والملفات الخاصة و`APP_KEY`.
7. مراجعة عطلات العرض وأنواع الإجازات وفق قانون العمل المعتمد.

## 8.1 جولة التحسين النهائية

- **توحيد المصطلحات العربية** في الواجهة وبيانات العرض والوثائق: «الأقسام / القسم» للأقسام (و«الإدارة» للوحة الإدارة فقط)، «الوظائف» للوظائف و«المسميات الوظيفية» للمسميات، «الاستقطاعات» لاستقطاعات الرواتب، «القضايا التأديبية»، «الأحداث الأولية»، «مراجعة تسجيلات الجوال والويب»، «مستخدمو الإدارة النشطون».
- **سجل التدقيق:** كل أحداث التدقيق (182 حدثًا) تظهر بتسمية عربية/إنجليزية في «آخر النشاطات» بلوحة التحكم وفي شاشات سجل التدقيق، مع صيغة مقروءة لأي مفتاح غير معروف، واختبار يمنع إضافة حدث بلا تسمية.
- **`.env.example`:** متغيرات `REPORTS_*` وبقية المتغيرات الخاصة بالمشروع.
- **نقل القيم التشغيلية من `.env` إلى الإعدادات:** قفل الدخول، مدة دخول تطبيق الجوال، SameSite / Secure لملف الجلسة، ترويسات الأمان وCSP وHSTS ومصادرها الإضافية، حد التصدير (الإعدادات ← الأمان)؛ حدود تصدير التقارير وأقصى صفوف PDF (مجموعة جديدة: الإعدادات ← التقارير)؛ أيام سجل التطبيق اليومي (الإعدادات ← الاحتفاظ بالبيانات). تُطبَّق وقت التشغيل مع قيم افتراضية ثابتة إن تعذرت قراءة قاعدة البيانات، وتنسخ ترحيلة لمرة واحدة أي قيمة ما زالت مضبوطة في `.env`. يبقى في `.env` فقط ما يلزم قبل الاتصال بقاعدة البيانات أو للبنية التحتية والأسرار (`APP_*`، `DB_*`، برامج التشغيل، `MAIL_*` كقيمة احتياطية، `APP_PREVIOUS_KEYS`، `SANCTUM_STATEFUL_DOMAINS` / `SANCTUM_TOKEN_PREFIX`، أدوات المطورين).
- **خطابات الموارد البشرية PDF** عبر `ArabicPdf` المشترك مع القسائم والتقارير.
- **المستودع:** ذاكرة خطوط mPDF (`storage/framework/mpdf`) لم تعد متتبَّعة.
